# 框架说明

客户端负责简单、稳定的使用入口；服务端负责明确的契约与可维护的部署。连接参数由部署者配置，普通用户通过配对码获得使用权限。

| 部分 | 职责 |
| --- | --- |
| 控制面 | 账号、配对码、设备凭据、配置下发、设备撤销、聚合统计和更新登记 |
| 数据面 | Xray / libv2ray 执行隧道连接；服务端通过 3x-ui 适配器管理数据面 |
| 客户端 | 绑定、连接状态、配置缓存、系统代理或 VPN 管理、界面交互 |
| Linux 守护进程 | 持有连接和系统代理；CLI 与 GUI 通过本地控制通道操作同一状态 |

Windows 与 Linux 通过源码链接共用连接状态、协议模型、配置生成和更新验签逻辑。Android 使用相同的 HTTP 契约。公开 API 定义位于 server/docs/openapi.yaml。

## 使用流程

1. 部署者配置服务器、HTTPS 和数据面，再构建三个客户端。
2. 管理员创建用户与配对码，使用者在客户端完成绑定。
3. 客户端获取设备配置，启动内核并检查连接；成功验证的配置可以缓存用于后续恢复。
4. Windows/Linux 接管系统代理前保存并校验恢复备份；停止时先恢复系统代理，再停止内核。恢复操作报错时保留内核与恢复信息，供后续重试。Android 显式停止会释放 VPN；启用断网保护后，意外故障保留阻断，主页可“停止并解除保护”或“重试连接”，通知也保留释放入口。服务端可撤销设备凭据。

## 运行边界

- 智能分流先阻断已可见的私网地址与 BT，再匹配国内域名直连、类别归因和国际服务域名代理；未命中的域名通过内置 DNS 解析 IP。解析集合中包含私网地址时优先阻断，包含国外公网地址时走代理，仅国内公网地址可命中国内 IP 直连。已命中域名不为 IP 规则额外解析，全局模式继续使用 AsIs。DNS 保留双栈缓存并启用组内并行查询；详细优先级、服务范围和限制见 [网络选路与优化](network-routing.md)。
- 公网客户端请求使用 HTTPS，验证证书链、有效期和主机名；API 不自动跟随重定向。
- 管理入口通过私有访问通道使用，设备 API 不返回管理凭据。
- 服务端 API 与具备数据面管理权限的 helper 分离，通过受保护的本地通道通信。
- 用量以聚合类别记录；管理接口可见设备出口地址，部署者可以配置历史保留范围。
- 新安装默认关闭自动更新检查；已有显式偏好保留。更新清单与产物需经过签名和摘要校验，未配置可信密钥时拒绝接受更新。
- Android 断网保护默认关闭；故障后实际仍在阻断时，主页主开关停止并解除保护，重试是独立动作。
- Android 下拉快捷设置中，单击 MyProxy 磁贴直接连接或断开，普通连接失败可单击重试，长按打开 APP。未配对、需要 VPN 授权或断网保护仍在阻断时进入 APP；首次授权由该次点击发起，授权完成后继续连接。连接和断开过程中忽略重复点击。
- Linux GUI 依赖已启动的守护进程；后台超时或不可用时，界面与托盘显示状态未知，清除旧流量和自检结果；收到有效状态后恢复显示。桌面能力仍需在目标桌面环境验收。
- Linux GNOME、KDE 与环境变量绕过相同的内网范围，包含 IPv4 私网/链路本地和 IPv6 回环、ULA、链路本地网段；环境变量使用等价的整字节 IPv6 前缀，以兼容部分 curl 版本。CIDR/IPv6 匹配仍取决于应用支持，停止时恢复用户原设置。
- 启动和重配通过隧道请求自有服务器的 /connectivity-check，要求空 HTTP 204。部署者可配置最多四个 HTTPS 检测地址，失败依次回退，单次最多五秒、整轮最多二十秒；用户取消会中止检测。三端手动自检共用十秒预算，按候选数量分配尝试时间。Windows/Linux 仅在有独立可信出口 IP 时用 Cloudflare trace 辅助核对；连接入口不是出口证据，地址族、NAT 或其它合法出口造成的不匹配保持未知，不据此判绕过或连接失败。
- 系统代理恢复依赖有效的备份和可写存储；连接、异常退出与恢复应在目标环境验证。

配置、安装和测试步骤见 [部署说明](deployment.md)。
