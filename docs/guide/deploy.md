# 部署指南

这篇文章按顺序讲一遍从零部署 MyProxy 要做的事，重点放在每一步为什么要做、容易在哪里出错。具体的命令、环境变量和参数，以参考里的[配置、构建与部署](../deployment.md)和[服务端部署](../../server/docs/DEPLOYMENT.md)为准；两边有出入时，以参考文档为准。

## 开始之前

你需要准备四样东西：

- **一台 Linux 服务器**，能运行 systemd、nginx 和 Python 3，并装好 3x-ui 与 Xray。部署脚本不会替你下载或安装这些第三方服务。
- **一个域名和正式的 HTTPS 证书。**证书要由公开 CA 签发（例如 Let's Encrypt），并带完整的证书链。客户端会严格校验证书，自签证书不能用于对外的入口。
- **一台用来构建客户端的电脑**，装好 .NET SDK 和 Python；如果要构建 Android 客户端，还需要 JDK 和 Android SDK。
- **用 SSH 密钥登录服务器的权限**，以及核验过的主机指纹。

仓库里出现的示例地址只是占位，不对应任何共享服务器、账号或安装包。每一处都需要换成你自己的。

## 第一步：准备数据面

数据面就是 Xray，它承载真正的代理流量。在 3x-ui 里新建一个 VLESS + REALITY 入站，生成密钥和 short ID，并设置一个有效的 SNI。MyProxy 只接受 REALITY 类型的入站，其他类型会被服务端拒绝。

端口要提前规划好。控制面的 HTTPS API 和 Xray 入站是两项独立的服务：如果它们在同一台主机上，就必须用不同的端口，比如一个用 443、另一个用 8443；如果分开部署在两台主机上，两边都可以用 443。

## 第二步：写好统一入口

整个项目只有一个地方需要填写服务器地址，就是仓库根目录的 `deployment.json`。把里面的 `api_base_url` 改成你自己的 HTTPS 地址：

~~~json
{
  "api_base_url": "https://api.example.com:8443"
}
~~~

这里只写协议、域名和端口，不要带路径、账号密码或查询参数；省略端口时默认使用 443。

三个客户端在构建时读取这个文件，服务端部署时也使用同一份文件，所以它就是整个系统的“唯一入口”。这也意味着：改了它，客户端必须重新构建，旧的安装包仍然指向旧地址。

如果你担心检测地址只有一个，可以在同一个文件里再加最多四个备用的连接检测地址，写法见参考文档。不加也完全没问题，默认只使用你自己的服务器，不依赖任何第三方探测服务。

## 第三步：部署服务端

服务端用仓库自带的部署脚本通过 SSH 安装。运行时需要明确告诉它服务器地址、SSH 私钥和证书文件的位置，并显式确认部署，避免误操作。脚本会替你处理这些事：

- 部署之前先校验配置，只上传运行所需的文件；
- 第一次安装时，生成独立的管理员令牌和设备签名密钥，存放在只有 root 和服务账户能读取的位置，之后不会自动更换；
- 让 API 只监听本机，由 nginx 对外公开设备 API 的白名单，管理接口和管理网页始终不对公网开放；
- 在改动之前，给服务目录、数据库、配置、nginx 和防火墙状态做快照，安装失败时自动恢复。

装好之后，先做三项检查再往下走：健康检查应该返回 200；连接检测地址应该返回 204，并且没有响应内容；从公网访问管理接口，应该得到 404。三项都符合，说明对外的入口是安全的。检查的具体写法见[服务端部署](../../server/docs/DEPLOYMENT.md)。

证书续期之后，记得让 nginx 重新加载；部署脚本不会改写你的公网证书。

## 第四步：构建并签名客户端

三个客户端都在你自己的电脑上构建，构建时会把统一入口里的地址带进安装包。

- **Windows**：用 .NET SDK 构建。
- **Android**：用 Gradle 构建 Release 版本。Release APK 默认没有签名，需要用你自己的长期密钥签名后再分发。请妥善保管这把密钥：以后的覆盖安装必须使用同一把密钥签名，否则系统会拒绝安装。
- **Linux**：构建命令行工具和托盘界面，另外需要一个版本匹配的 Linux Xray 内核。仓库提供了获取和打包的脚本，会核对内核的版本与摘要。

正式打包之前，运行仓库里的发布校验，它会检查配置和产物是否满足发布要求。统一入口如果仍是占位地址，生产打包会直接拒绝。

## 第五步：把配对码交给使用者

管理后台只能经过私有通道打开，通常是 SSH 隧道。在后台创建用户，生成配对码，复制后通过安全的渠道发给对应的人。配对码默认一小时内有效，也可以选一天或七天；关闭窗口之后，后台不再显示它的明文。

使用者装好客户端、输入配对码，就可以开始使用了。可以把[使用客户端](clients.md)这篇文章一起发给他们。

正式交出去之前，建议用自己的设备完整走一遍：绑定、连接、断开，再在后台撤销这台设备，确认每一步都符合预期。

## 日常维护

部署完成之后，还有几件需要长期照看的事：

- **证书**：确认自动续期在正常工作，每次续期后重新加载 nginx。
- **防火墙**：在主机和云服务商的防火墙里放行 API 端口和 Xray 端口；私有的管理端口始终不对公网开放。
- **备份**：数据库里有设备记录和地址信息，备份时按私有数据处理。
- **出了问题**：设备丢失或怀疑凭据泄露时，先在后台撤销受影响的设备，再排查其他问题。
- **发布更新**：如果希望客户端能收到更新，先配置发布签名密钥和客户端内置的公钥，再用后台的“发布指派”向导签名、上传并指派版本，步骤见[图形化发布与指派](../release-publishing.md)。
