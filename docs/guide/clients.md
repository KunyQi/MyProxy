# 使用客户端

这篇文章写给拿到配对码的使用者。Windows、Android 和 Linux 三个客户端的用法基本一样：第一次绑定，之后只用开关。如果你还没有配对码，请先向你的管理员索取。

## 第一次绑定

打开客户端，在“首次绑定”页面输入管理员发给你的 8 位配对码，由字母或数字组成，然后点“绑定”。绑定成功后，客户端会记住这台设备，以后打开就直接进入主页，不需要再输入。

如果绑定没有成功，提示通常会告诉你原因：

- **配对码无效**：多半是输错了，检查一下再试。
- **配对码已过期**：配对码有有效期，请管理员重新生成一个。
- **无法验证服务器身份**：服务器的证书有问题，这不是你的设备的问题，请联系管理员。
- **尚未配置服务器**：这个安装包在构建时没有填写服务器地址，请联系提供安装包的人。
- **请求过于频繁**：稍等一会儿再试。

## 连接与断开

主页中间是连接开关。按下之后，状态会显示“正在连接…”。这时客户端不只是启动连接，还会通过隧道确认网络真的能走通，确认之后才显示“已连接”和“网络连接正常”。再按一次就会断开。

想确认当前连接是否正常，可以点“检测连接”（Android 上叫“检查连接”），客户端会重新检查一次，并显示当前的延迟。

## 两种连接模式

在主页可以随时切换连接模式，切换时会短暂显示“正在切换…”。

- **智能分流**（默认）：国内网站直连，其余走代理。日常使用推荐这个模式，访问国内网站时不必绕道服务器。
- **全局代理**：所有网站都走代理。

无论哪种模式，私网地址和 BT 流量都会被阻断。

## 设置

设置页里的选项不多，每一项都可以按需要打开：

- **启动后自动连接**：打开客户端时自动连上。
- **自动启动客户端**（Windows、Linux）：开机后自动启动客户端。
- **自动检查更新**：默认关闭。打开后，客户端会定期检查新版本；检查到更新也不会自动安装，需要你确认。所有更新都要先通过部署者签名的校验。Linux 上这个开关目前只保存在托盘界面里，还不会改变后台的定期检查。
- **界面外观**（Windows、Linux）：在经典、瓷白、釉陶三套外观之间切换，只改变界面的样子。
- **查看日志**（Windows、Linux）：出现问题时，可以打开日志发给管理员。发送之前，请先删掉其中可能涉及隐私的内容。
- **重新绑定**：会停止连接并清除这台设备上的凭据，之后需要重新输入配对码。一般只在管理员让你这样做时才需要。

## Android 上的几个功能

**快捷设置磁贴。**把 MyProxy 磁贴加到下拉快捷设置里，之后单击磁贴就能直接连接或断开；连接失败时，单击可以重试；长按会打开 App。如果设备还没有绑定、需要授予 VPN 权限，或者正处于断网保护中，单击磁贴会进入 App 处理。

**VPN 授权。**第一次连接时，系统会询问是否允许 MyProxy 建立 VPN 连接，选择允许即可。

**断网保护**（默认关闭）。打开之后，如果连接意外中断，客户端会阻断全部流量，避免流量在你不知情时绕过代理。此时状态会显示“流量已阻断”，你可以在主页选择“停止并解除保护”，或者“重试连接”；通知栏里也保留了“释放”的入口。

**自动修复。**灭屏且连接空闲时，客户端会自动重启运行异常的连接。

**后台限制。**如果主页提示“后台限制可能中断连接”，轻触提示，按系统的指引关闭对 MyProxy 的电池或后台限制，连接会更稳定。

## Linux 上的使用方式

Linux 客户端由三部分组成：负责连接的后台守护进程、命令行工具 `myproxy`，以及托盘界面 `myproxy-gui`。命令行工具和托盘界面都只是遥控守护进程，所以关闭托盘界面并不会断开连接；要断开，请使用“停止代理”。

第一次使用时，先在终端里用 `myproxy bind` 加上你的配对码完成绑定，这一步同时会启动守护进程；然后再打开托盘界面。之后既可以在托盘界面里操作，也可以在终端里用 `myproxy start`、`myproxy stop` 和 `myproxy status` 连接、断开和查看状态。

系统代理支持 GNOME、KDE 和环境变量三种方式，局域网和本机地址会自动绕过，断开时恢复你原来的设置。托盘图标和菜单的表现取决于你的桌面环境。

## 遇到问题时

- **无法连接服务器**：先确认这台设备本身能正常上网，再重试。
- **连接失败**：按“重试”再试一次；仍然不行，可以查看日志，联系管理员。
- **设备已失效，请重新绑定**：这台设备被管理员撤销了，需要向管理员要一个新的配对码。
- **系统代理设置失败或恢复失败**（Windows）：按提示重试；如果仍然失败，重启客户端。
- **本地端口被占用**：通常稍等片刻再试就好；如果反复出现，查看日志并联系管理员。
