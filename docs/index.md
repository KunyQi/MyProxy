# MyProxy

**把复杂留在代码里，用户只管连接。**

MyProxy 是一套自建 VPN。你在自己的服务器上部署控制面，再把 Windows、Android 和 Linux 三个客户端交给要用的人。部署这一次，需要一位懂网络的人来完成；在那之后，使用者只在第一次打开客户端时输入一个 8 位配对码，往后每天要做的事只有一件：打开或关闭连接。

## 特点

<div class="grid cards" markdown>

- **一次配对，之后只用开关**

    使用者只需要输入一个 8 位配对码。服务器地址、证书和协议都由部署者预先配好，使用者从头到尾不用看到它们。

- **流量走你自己的服务器**

    客户端和你服务器上的 Xray 直接建立 VLESS + REALITY 连接，中间没有任何第三方 VPN 服务商。

- **智能分流，开箱即用**

    默认国内网站直连、其余走代理，私网地址和 BT 流量始终阻断。需要时，在主页一键切换成全局代理。

- **连得通，才算连上**

    每次连接都会经隧道访问你自己服务器上的检测地址，确认真正可用才显示“已连接”，不依赖任何公共探测站。

- **按设备管理，随时撤销**

    每台设备都有自己的凭据。设备丢了，管理员在后台撤销这一台即可，其他人照常使用。

- **不给系统留烂摊子**

    Windows 和 Linux 接管系统代理前先备份并校验原设置，断开时先把它恢复。Android 可以开启断网保护，连接意外中断时阻断流量，不让它悄悄绕开代理。

- **三端一致，轻量无广告**

    Windows、Android 和 Linux 共用同一套接口契约和同一份服务器入口。界面只留下必要的操作，Android 支持快捷设置磁贴，桌面端还有经典、瓷白、釉陶三套外观。

- **更新可信，绝不擅自安装**

    更新必须通过部署者自己密钥的签名和摘要校验。默认不检查更新；即使检查到新版本，也要使用者确认才会安装。

- **部署可复现，配置可审查**

    一份入口配置决定所有客户端和服务端连向哪里。部署脚本先预检、再变更，失败时自动恢复快照；服务端接口有公开的 OpenAPI 契约。

- **开源，归你所有**

    采用 MIT 许可，源码、构建和部署都在你手里。缺什么，就补什么，也可以把改进留给下一个人。

</div>

## 为什么做它

自建 VPN 的开源工具早已足够强大，真正难的是“交给别人用”这一步。协议、地址、端口、证书，每一项都要使用者先弄明白，才能连上。商业 VPN 把这些藏了起来，代价是把流量交给第三方。

MyProxy 想两样都要：流量走你自己的服务器，用起来又像商业 VPN 一样简单。服务器、证书和连接参数由部署者一次填好，使用者按默认策略就能连接，不必先学习网络配置。

## 它由什么组成

**三个客户端。** Windows、Android 和 Linux，界面只留下连接开关、连接模式和少量设置，没有广告。三端读取同一份服务器入口，换服务器时只需要改一处、重新构建。

**一套控制面。** 用 Python 写成的服务端，负责账号、配对码、设备凭据、配置下发和设备撤销，并按类别聚合统计用量。它只回答“谁能用、用什么配置”，不转发任何代理流量。

**你自己的数据面。** 服务端保留 3x-ui 面板来管理 Xray，客户端与 Xray 之间直接建立 VLESS + REALITY 连接。服务器和流量都在你自己手里。

## 用起来是什么样

对使用者来说，整个过程只有三步。管理员在后台为他创建账号，生成一个配对码发给他；他在客户端里输入配对码，完成绑定；之后每次只需要按下连接开关。

默认的“智能分流”让国内网站直连、其余流量走代理，日常使用不需要任何调整；需要时也可以切换成“全局代理”。在 Android 上，还可以从下拉的快捷设置里单击 MyProxy 磁贴，直接连接或断开。

## 项目现状

MyProxy 目前是 0.1.x 公开测试版，面向自行部署服务器的开发者。仓库提供源码和构建输入，不提供预制安装包，也没有现成的线上服务。

Android 客户端已经通过实机测试；Windows、Linux 和服务端有完整的构建与回归测试，桌面环境下的集成行为仍需要在目标系统上验收。项目自身的代码与文档采用 [MIT](../LICENSE) 许可，第三方组件保留各自的许可，详见[第三方声明](../THIRD_PARTY_NOTICES.md)。
